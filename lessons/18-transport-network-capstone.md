# 18. 교통망 분석 종합 실습

## 목표와 어휘

이번 수업의 목표는 새 알고리즘을 만드는 것이 아니라, 앞에서 구현한 알고리즘을 한 분석기에 올바르게 조합하는 것입니다.

- **연결 요소**: 서로 경로로 도달할 수 있는 정점의 최대 묶음
- **깊이 우선 탐색**(Depth-First Search, DFS): 한 경로를 끝까지 따라간 뒤 되돌아오는 탐색
- **최단 경로**: 두 정점 사이에서 가중치 합이 가장 작은 경로
- **최소 신장 트리**(Minimum Spanning Tree, MST): 연결 무방향 그래프의 모든 정점을 잇는 최소 비용 트리

## 고정 교통망

도시 사이의 양방향 이동 비용을 다음처럼 표현합니다.

```python
graph = {
    "A": {"B": 1, "C": 5},
    "B": {"A": 1, "C": 2},
    "C": {"A": 5, "B": 2},
}
```

`A-B`가 양방향 비용 1이라는 뜻이므로 `graph["A"]["B"]`와 `graph["B"]["A"]`가 모두 1이어야 합니다. 분석기는 `A`에서 `C`로 가는 경로를 묻고 다음 네 값을 보고합니다.

- `connected`: 전체 교통망이 하나의 연결 요소인가?
- `route`: `start`에서 `end`까지의 최소 비용 경로는 무엇인가?
- `distance`: 그 경로의 비용은 얼마인가?
- `infrastructure_cost`: 모든 도시를 연결하는 최소 건설 비용은 얼마인가?

## 코딩 전에 알고리즘 선택하기

구현을 보기 전에 각 질문에 맞는 알고리즘을 먼저 고르세요.

1. 전체 연결성에는 Lesson 4의 `connected_components`를 사용합니다. 가중치는 연결 여부에 필요 없으므로 이웃 키만 집합으로 바꿉니다.
2. 비음수 이동 비용의 최단 거리와 부모에는 Lesson 8의 `dijkstra`를 사용합니다.
3. 부모 딕셔너리에서 실제 경로를 얻을 때는 Lesson 3의 `reconstruct_path`를 사용합니다.
4. 연결된 무방향 교통망의 최소 건설 비용에는 Lesson 11의 `kruskal`을 사용합니다.

연결성은 **전체 그래프**에 관한 질문이고, 경로는 **`start`에서 `end`까지**의 질문입니다. 둘을 혼동하면 다른 성분이 있어도 목적지에만 도달하는 경우 `connected`를 잘못 `True`로 보고할 수 있습니다. 전체가 연결되지 않았다면 최소 신장 트리는 없으므로 `infrastructure_cost`는 `None`입니다.

## 입력 계약과 검증

`analyze_transport_network(graph, start, end)`는 다음을 먼저 확인합니다.

1. `start`와 `end`가 모두 `graph`의 정점이어야 합니다.
2. 모든 이웃도 `graph`의 정점이어야 합니다.
3. `source → target`이 있으면 같은 가중치의 `target → source`도 있어야 합니다.
4. 가중치는 음수가 아니어야 합니다. 이 조건은 기존 `dijkstra`가 검사합니다.

세 번째 조건이 필요한 이유는 연결 요소와 Kruskal 알고리즘이 이 입력을 무방향 그래프로 해석하기 때문입니다. 방향이나 반대 방향의 비용이 다르면 하나의 무방향 건설 비용으로 바꿀 근거가 없습니다.

## 스켈레톤에서 완성본으로

연습 파일은 입력 검증, 무가중 그래프 변환, 기존 함수 호출까지 제공합니다. 학습자가 채울 부분은 두 곳입니다.

1. 인접 맵에 두 번 저장된 무방향 간선을 Kruskal 입력에 한 번만 넣습니다. 정점 이름이 문자열이므로 `source < target`인 방향만 남기면 됩니다.
2. 네 결과를 정확한 키의 딕셔너리로 조립합니다. 도달할 수 없는 `end`는 기존 함수의 결과에 따라 경로가 `None`, 거리가 `float("inf")`가 됩니다.

고정 교통망에서는 Dijkstra가 `A → B → C`와 거리 3을 찾습니다. Kruskal은 비용 1의 `A-B`와 비용 2의 `B-C`를 골라 총 3으로 모든 도시를 잇습니다.

## 정당성과 복잡도 과제

완성한 뒤에는 코드만 제출하지 말고 다음을 설명하세요.

- 연결 요소가 하나일 때와 아닐 때 `connected`가 왜 정확한가?
- Dijkstra의 거리와 부모를 복원한 `route`가 왜 최소 비용 경로인가?
- `source < target` 필터가 왜 무방향 간선을 빠뜨리지도, 중복하지도 않는가?
- 연결된 경우 Kruskal의 합이 왜 최소 기반 시설 비용인가?

정점 수를 `|V|`, 무방향 간선 수를 `|E|`라 하겠습니다. 검증, 변환, 연결 요소 계산은 `O(|V| + |E|)`, 이진 힙을 쓰는 Dijkstra는 `O((|V| + |E|) log |V|)`, Kruskal의 정렬은 `O(|E| log |E|)`입니다. 따라서 전체 최악 시간은

`O((|V| + |E|) log |V| + |E| log |E|)`

이고 추가 공간은 `O(|V| + |E|)`입니다.
