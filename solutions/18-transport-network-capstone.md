# 18. 교통망 분석 종합 실습 해답

## 1. 알고리즘 선택

| 분석 질문 | 사용할 기존 함수 | 선택 이유 |
|---|---|---|
| 전체 그래프가 연결되었는가? | `connected_components` | 가중치를 버린 그래프에서 깊이 우선 탐색(Depth-First Search, DFS)으로 연결 요소 수를 센다. |
| `A`에서 모든 정점까지의 최소 비용은? | `dijkstra` | 모든 가중치가 음수가 아닐 때 한 시작점 최단 거리를 구한다. |
| 부모 딕셔너리에서 `A → C` 경로는? | `reconstruct_path` | Dijkstra가 기록한 부모를 목적지부터 따라가 실제 경로를 복원한다. |
| 모든 도시를 잇는 최소 건설 비용은? | `kruskal` | 연결 무방향 그래프에서 최소 신장 트리(Minimum Spanning Tree, MST)를 구한다. |

각 함수는 서로 다른 질문에 답합니다. 특히 `connected`는 `A → C`의 도달 가능성이 아니라 전체 그래프의 연결성을 뜻합니다.

## 2. 예상 보고서 손계산

직접 간선 `A-C`의 비용은 5이고 `A-B-C`의 비용은 `1+2=3`이므로 최소 경로는 `A-B-C`입니다. 세 정점이 하나의 연결 요소에 있고, Kruskal은 가장 싼 `A-B(1)`, `B-C(2)`를 골라 사이클 없이 모두 연결합니다.

```python
{
    "connected": True,
    "route": ["A", "B", "C"],
    "distance": 3,
    "infrastructure_cost": 3,
}
```

## 3. 입력 검증의 이유

1. `start`나 `end`가 없으면 출발 거리 초기화 또는 최종 거리 조회가 정의되지 않으므로 분석기가 직접 `ValueError`를 냅니다.
2. 이웃이 정점 키가 아니면 그 정점의 인접 정보를 읽을 수 없습니다. 대칭 무방향 간선 검사에서 이를 거부합니다.
3. 한쪽 간선이 없거나 비용이 다르면 하나의 무방향 교통로로 해석할 수 없습니다. 같은 대칭 검사에서 이를 거부합니다.
4. Dijkstra는 음수 간선에서 최단 거리를 보장하지 않습니다. 기존 `dijkstra`의 비음수 검사에 맡겨 `ValueError`를 냅니다.

Kruskal도 연결된 무방향 입력을 전제로 합니다. 먼저 전체 연결성을 검사하므로, 연결되지 않은 그래프에서는 Kruskal을 호출하지 않고 `infrastructure_cost=None`을 반환합니다.

## 4. 테스트 사례 설계

1. 제시된 삼각형에서 전체 보고서가 `True`, `A-B-C`, `3`, `3`인지 확인합니다. 이는 잘못된 알고리즘 조합이나 보고서 키·값 조립을 잡습니다.
2. `{"A": {"B": 1}, "B": {"A": 1}, "C": {}}`에서 `A → C`를 물으면 `connected=False`, `route=None`, `distance=float("inf")`, `infrastructure_cost=None`이어야 합니다. 이는 목적지 도달성과 전체 연결성을 섞거나 단절 그래프에서 Kruskal을 부르는 오류를 잡습니다.
3. `{"A": {"B": 1}, "B": {}}`는 반대 방향 간선이 없으므로 `ValueError`를 내야 합니다. 이는 방향 입력을 무방향으로 잘못 받아들이는 오류를 잡습니다.

## 5. 정당성과 복잡도

가중치를 버려도 정점 사이에 간선이 있는지는 변하지 않습니다. 따라서 DFS 연결 요소가 하나인 것과 전체 교통망이 연결된 것은 동치이고 `connected`는 정확합니다. 입력의 모든 가중치는 Dijkstra가 검사한 비음수이므로 Dijkstra의 `distances[end]`는 `start`에서 `end`까지의 최소 비용입니다. 그때 기록한 부모를 `reconstruct_path`가 역으로 따라가므로 `route`는 그 거리를 만드는 실제 경로이며, 도달하지 못하면 부모가 없어 `None`입니다.

대칭 검사를 통과한 서로 다른 두 정점 `u`, `v`의 무방향 간선은 인접 맵에 `u → v`, `v → u`로 정확히 두 번 있습니다. 문자열의 전순서에서 둘 중 정확히 하나만 `source < target`을 만족하므로 필터는 간선을 빠뜨리거나 중복하지 않습니다. 전체 그래프가 연결된 경우 이 간선 목록에 Kruskal을 적용하면 모든 정점을 잇는 최소 가중치 신장 트리를 얻으므로 그 합은 최소 기반 시설 비용입니다. 연결되지 않으면 하나의 신장 트리가 존재하지 않으므로 `None`이 맞습니다.

입력 검증, 무가중 변환, DFS 연결 요소 계산은 `O(|V|+|E|)`입니다. 이진 힙 Dijkstra는 `O((|V|+|E|) log |V|)`, 경로 복원은 `O(|V|)`, 간선 변환은 `O(|E|)`, Kruskal은 정렬 때문에 `O(|E| log |E|)`입니다. 전체 최악 시간은 `O((|V|+|E|) log |V| + |E| log |E|)`, 추가 공간은 `O(|V|+|E|)`입니다.

## 6. 최종 성찰

예를 들어 이 분석기는 **최대 유량**을 구하지 않습니다. 연결 여부, 한 쌍의 최단 경로, 전체 연결의 최소 비용만 반환하며 간선 용량이나 여러 경로에 흐름을 나누는 조건을 입력으로 받지 않기 때문입니다.
